У Hyprland ровно **один** слот шейдера — `decoration:screen_shader`. Из-за этого ночной тёплый фильтр, затемнение и кинескоп взаимно исключают друг друга: выигрывает тот, кого выставили последним, остальные просто пропадают. Менеджер забирает слот себе и **композирует**: каждый эффект — это один файл с единственной функцией `vec3 effect(vec3 c, vec2 uv)`, а из активных плюс множителя яркости собирается один сгенерированный шейдер

Яркость тоже софтверная: на десктопе подсветку крутить нечем, поэтому затемнение — это умножение цвета. Заодно оно уходит ниже "железного" минимума и поднимается выше 100%

Перекочевало из моего райса **[rokokol/huix](https://github.com/rokokol/huix)**

```sh
# примерить на живой сессии, ничего не устанавливая
nix run github:rokokol/hyprland-screen-shader -- flash crt 3
```

## Эффекты

| | | |
| --- | --- | --- |
| ⚫ `grayscale` | 🟤 `sepia` | 🔄 `invert` |
| 🌅 `warm` — режет синий, на вечер | ❄️ `cool` | 🎯 `vignette` |
| 📖 `reading` — зелёная бумага без бликов | 🎨 `posterize` | 🌈 `none` — только затемнение |
| 🔪 `sharpen` — ядро 3×3 | 📺 `crt` — кривизна, теневая маска, скан-линии | 🟢 `matrix` — цифровой дождь |
| 💾 `jpeg` — блочность DCT и звон | 🌊 `wave` — медленная рябь | 📡 `glitch` — RGB-split и рвущиеся строки |

Они **стакаются**. `effect push` кладёт фильтр поверх текущих, `effect toggle` добавляет или убирает, `effect clear` сбрасывает всё. Эффекты, которые сэмплят текстуру со смещением (`crt`, `wave`, `glitch`, `jpeg`, `sharpen`), идут в цепочке первыми, цветовые — после: сначала геометрия, потом покраска результата. Два геометрических честно в один проход не сложить, поэтому последний перекрывает предыдущий

## Установка

### Home Manager

```nix
{
  inputs.screen-shader.url = "github:rokokol/hyprland-screen-shader";

  # в домашней конфигурации
  imports = [ inputs.screen-shader.homeManagerModules.default ];

  programs.screen-shader = {
    enable = true;
    waybar = {
      signal = 8;
      bars = [ "mainBar" ];
    };
  };
}
```

Это вся настройка. Включение ставит пакет, вешает бинды, объявляет пикер как rofi-modi (со своим эмодзи режима) и определяет модуль `custom/shader` в перечисленных барах. Остаётся только решить, *где* в баре стоять индикатору — добавить `"custom/shader"` в `modules-right` (или left, или center; вот это угадать невозможно)

| Клавиши | Действие |
| --- | --- |
| `SUPER SHIFT + G` | пикер: все эффекты плюс кнопки яркости |
| `SUPER + G` | сбросить стопку |
| `SUPER CTRL + ]` / `[` | яркость ±5%, повторяется при удержании |
| `SUPER CTRL + Backspace` | яркость обратно в 100% |

Меняется через `hyprland.modifier`, либо заменой всего `hyprland.settings`, либо `{ }` — и вешаешь бинды сам

### Любой другой дистрибутив

```sh
git clone https://github.com/rokokol/hyprland-screen-shader
cd hyprland-screen-shader
sudo ./install.sh          # PREFIX=~/.local ./install.sh — поставить в пользователя
```

Собирать нечего: скрипты и эффекты копируются в `$PREFIX/share/screen-shader` и линкуются в `$PREFIX/bin`. Свою директорию скрипты вычисляют сами, разрешая симлинк, так что путь к эффектам нигде не прописывается

Нужны `bash`, `awk`, `sed`, `grep`, `flock`, `hyprctl` и — для пикера — `rofi`. `notify-send` необязателен: без него сообщения идут в stderr

Бинды в этом случае свои:

```conf
bind  = SUPER SHIFT, G, exec, rofi-shader
bind  = SUPER, G, exec, screen-shader effect clear
bindel = SUPER CTRL, bracketright, exec, screen-shader bright up
bindel = SUPER CTRL, bracketleft, exec, screen-shader bright down
bind  = SUPER CTRL, BackSpace, exec, screen-shader bright reset
exec  = screen-shader restore
```

Именно `exec`, а не `exec-once`: слот шейдера — рантайм-состояние, его надо применять заново на каждый reload

## Команды

```sh
screen-shader effect push|set|toggle|clear|next|prev <имя>
screen-shader bright up|down|reset|toggle|set <0.10..2.00>|get
screen-shader add <file.frag> [флаги]       # поставить эффект прямо сейчас, без ребилда
screen-shader remove <имя>                  # и убрать обратно
screen-shader flash [-k] <имя> [секунды]    # поверх стопки, durable state не трогает
screen-shader restore                       # применить сохранённый выбор
screen-shader reset-all                     # эффекты и яркость одним движением
screen-shader status                        # JSON для waybar-модуля
screen-shader menu                          # "<эмодзи> <подпись>|<имя>" для пикера
```

`flash` сделан для вызова снаружи: подмешивает эффект поверх текущего на секунду-другую и возвращает как было, не трогая durable-состояние. С `-k` он молча ничего не делает, если стопка занята, — чтобы не спорить с осознанным выбором

Выбор (стопка и яркость) лежит в `$XDG_STATE_HOME/screen-shader/state` и переживает перезагрузку. Сгенерированные шейдеры эфемерны, в `$XDG_RUNTIME_DIR/screen-shader`

## Как добавить свой эффект

Эффект — это **один файл**, и всё: ни списка, куда дописывать имя, ни таблицы, которую надо держать в синхроне. Регистрация — это факт появления файла в директории шейдеров, менеджер пересканирует её на каждый вызов.

### Что должно быть в файле

```glsl
// label: Bloom          <- что покажет пикер
// emoji: 🔆             <- рядом с подписью и в индикаторе waybar
// order: 65             <- место в меню и в effect next/prev
// animated: no          <- эффект не зависит от времени
// samples: yes          <- пиксель берёт цвет из другого места экрана, а не только из себя

vec3 effect(vec3 c, vec2 uv) {
    vec3 blur = texture(tex, uv + vec2(0.002)).rgb;
    return max(c, blur * 0.8);
}
```

Два обязательных условия:

- **ровно одна функция `vec3 effect(vec3 c, vec2 uv)`**, возвращающая новый цвет. Это точка входа, которую зовёт менеджер
- **заголовок**, каждая строка — комментарий `//` вида `ключ: значение`. У любого ключа есть значение по умолчанию, так что эффект без заголовка заработает — но плохо: в конце меню под именем файла и с 🎬, и отрисованный так, будто он не двигается и не смотрит дальше своего пикселя. Два последних ключа как раз те, которые стоит проставить правильно — см. [режим отрисовки](#режим-отрисовки)

Что даётся даром — объявлять самому **не надо**:

| в области видимости | это |
| --- | --- |
| `c` | цвет на текущий момент: экран либо результат предыдущего эффекта стопки |
| `uv` | экранные координаты, 0..1 |
| `tex` | текстура экрана, если нужно сэмплить не в `uv` |
| `time` | секунды с запуска, float |
| `BRIGHTNESS` | текущий множитель софт-яркости |

Не пиши `#version`, `precision`, объявления `in`/`out`/`uniform` и `main()` — менеджер выдаёт всё это сам, а вторая копия будет ошибкой компиляции. Вспомогательные функции и константы на уровне файла — можно, и их имена могут совпадать с чужими: при композиции последующие тела переименовываются (`hash` → `hash_1`).

Имя файла и есть имя эффекта: `bloom.frag` даёт `screen-shader effect push bloom`.

### Две директории: объявленная и добавленная

Эффекты читаются из **двух** мест, в таком порядке:

| | это | пишет | переживает |
| --- | --- | --- | --- |
| **объявленные** | `$SCREEN_SHADER_DIR` — то, что приехало вместе с установкой. Под Nix это путь в сторе, только на чтение | `install.sh`, клон или `programs.screen-shader.extraShaders` | ребилд воссоздаёт её ровно такой; больше её никто не трогает |
| **добавленные** | `$SCREEN_SHADER_USER_DIR`, по умолчанию `$XDG_DATA_HOME/screen-shader/shaders` | `screen-shader add` / `remove` | это твои данные, а не пакет — ребилд к ней не подходит |

Имя, которое есть в обеих, берётся из **добавленной**, так что `add` умеет и перекрывать поставляемый эффект. `remove` удаляет только из добавленной, то есть открывает обратно объявленный эффект с тем же именем, а не уничтожает его.

Это разделение и делает обе половины честными под Nix: декларативная воспроизводима и живёт в конфиге, императивная — чтобы попробовать прямо сейчас, ценой того, что в конфиге её нет. Когда эффект прижился, переноси его в `extraShaders`, а добавленную копию сноси через `remove`.

```nix
programs.screen-shader.extraShaders.bloom = ./bloom.frag;
```

### Добавить прямо сейчас

```sh
screen-shader add ~/bloom.frag --label Bloom --emoji 🔆 --order 65 --samples
```

Флаги пишутся строками заголовка **поверх** файла, а те же ключи вырезаются из копии ниже — так что шейдер, ничего не знающий про этот менеджер, всё равно ложится с заголовком, а тот, у которого заголовок свой, сохраняет всё, что флаги не перекрыли.

| флаг | |
| --- | --- |
| `--name <n>` | имя эффекта; по умолчанию — имя файла |
| `--label` / `--emoji` / `--order` | как выглядит в пикере |
| `--animated` / `--samples` / `--raw` | булевы ключи заголовка; `--no-animated` и прочие — наоборот |
| `-f` | заменить добавленный ранее |

### Шейдер, написанный не под этот менеджер

Обычный полноэкранный шейдер Hyprland — со своим `#version`, `main()` и записью в `fragColor` — заходит через `--raw`:

```sh
screen-shader add ~/blue-light.frag --raw --label "Blue light" --emoji 🔵 --order 45
```

Он отдаётся Hyprland ровно таким, каким написан, не считая строк заголовка. Честная цена: он **владеет кадром**. У него собственный `main()`, поэтому с ним ничего не композируется — выбор такого эффекта сбрасывает стопку, выбор любого другого сбрасывает его, а софт-яркости негде умножаться: сгенерированного `main()`, куда положить множитель, просто нет.

Без `--raw` файл с `main()` отвергается с этим же объяснением — вместо того чтобы молча собраться в шейдер, который никогда не скомпилируется.

`extraShaders` подмешивается к штатному набору, поэтому ключ с уже существующим именем **заменяет** штатный эффект — так же перекрашивается или переставляется любой мой, без форка.

### Как проверить

```sh
screen-shader menu | grep bloom       # покажет, так ли прочитан заголовок
screen-shader effect set bloom        # применит
```

Ошибку в **имени** менеджер поймает громко — проверит, что файл есть, и скажет. А вот **ошибку GLSL — нет**: Hyprland принимает несобирающийся шейдер молча (`hyprctl` отвечает `ok`, `getoption` показывает его выставленным, в `hyprland.log` не попадает ничего), так что единственный симптом — эффекта просто не происходит. Проверять самому:

```sh
glslangValidator -S frag "$XDG_RUNTIME_DIR"/screen-shader/active-*.frag
```

В клоне это даётся даром: `nix flake check` компилирует каждый эффект отдельно и в композиции со всеми остальными. Иначе коллизию имён или забытый `main()` заметишь только по тому, что экран не изменился.

### Режим отрисовки

Hyprland надо сказать, насколько усердно перерисовывать, и это берётся из строк `animated:` и `samples:` заголовка. Принимаются `yes`/`true`/`on`/`1`, регистр не важен; **всё остальное, включая отсутствие строки, — это no**.

| | объявлено | `damage_tracking` / `vfr` | почему |
| --- | --- | --- | --- |
| анимация | `animated: yes` | `0` / `0` | нужен кадр на каждый тик; при VFR Hyprland уходит в idle и анимация дёргается |
| смещение | `samples: yes` | `1` / `1` | смещённая выборка читает соседние области, которые точный damage ещё не отрисовал — перерисовываем весь монитор, но в простое спим |
| обычный | ни того, ни другого | `2` / `1` | попиксельный эффект, частичный damage ок |

`samples: yes` заодно ставит эффект в цепочке **первым**, перед цветовыми фильтрами: сначала геометрия, потом покраска результата.

Ошибка вверх стоит лишних перерисовок, а вниз — как раз то, что видно глазами: анимация стоит на месте, искажение размазывается по неперерисованной области. Поэтому `nix flake check` сверяет половину про `animated` с компилятором: рефлексия перечисляет только реально используемые униформы, так что эффект, у которого `time` пережил компиляцию, а `animated: yes` не написан, роняет сборку.

## Waybar

`waybar.bars` определяет модуль, место выбираешь сам:

```nix
programs.waybar.settings.mainBar.modules-right = [ "custom/shader" "clock" ];
```

ЛКМ — пикер, ПКМ — полный сброс, СКМ — яркость пополам, колесо — яркость. Модуль прячется, когда эффектов нет и яркость 100%

Индикатор обновляется по `SIGRTMIN+N`, где `N` берётся из `waybar.signal` — объявляется один раз и запекается в пакет, поэтому скрипт и бар не могут разойтись в номере. **Дефолтное действие RT-сигнала — завершить процесс**, поэтому слать его до того, как waybar поставил обработчик, нельзя; `screen-shader restore` именно поэтому не шлёт ничего, а на старте сигнал и не нужен — waybar сам читает `status`

## Тесты

```sh
tests/run.sh              # 69 проверок, композитор не нужен
tests/run.sh --update     # перезаписать эталонные шейдеры после осознанного изменения
```

`hyprctl` и `notify-send` подменены заглушками, состояние уходит во временную директорию, а сгенерированный GLSL сравнивается с закоммиченными эталонами — так изменение в сборке шейдеров всплывает диффом, а не сюрпризом при следующем логине. `nix flake check` гоняет сьют плюс: каждый эффект отдельно и все разом через `glslangValidator`, полноту заголовков и совпадение их `animated:` с тем, что компилятор оставил живым, обёртки пакета и модуль Home Manager, вычисленный против заглушек опций
